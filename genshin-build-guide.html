Overview

What the app does.

From browsing the full character roster to publishing a guide other players can learn from.

Genshin Build Guide is a community-style guide platform: players browse the game's 92 playable characters, pick one, and write a build guide covering the artifacts, weapons, and strategies that make that character work.

Character data is seeded from a public Genshin Impact API into a local SQLite database, so the roster is always complete without any manual data entry. Guides support multiple image uploads with captions, and every new guide enters a pending state until approved — keeping the public listing clean.

Everything a user submits is validated again on the server, so bad data can't sneak past the frontend, and the whole flow is covered by Cypress end-to-end tests that exercise the real API.

A guide's journey

  • 1Browse the roster. The home page lists all 92 characters, four per page, each linking to a detail view.
  • 2Log in. JWT authentication protects the guide-creation routes; tokens expire after 24 hours.
  • 3Write the guide. Title, description, character pick, and optional JPG/PNG images with captions.
  • 4Server validates. Field lengths, formats, and file rules are enforced by Pydantic on the backend.
  • 5Pending → approved. New guides await approval before appearing in the public, paginated listing.

Approval workflow

New guides start as “pending” and only approved guides appear in the public listing — a moderation layer built into the data model from day one.

JWT authentication

Login issues a JSON Web Token that protects guide-creation routes. Tokens expire after 24 hours and gate the app's protected pages.

JWT Protected routes

Server-side validation

Every field is re-validated on the backend with Pydantic, so frontend validation can't be bypassed — lengths, formats, file types, and size limits.

Pydantic Defense in depth

End-to-end testing

Cypress suites cover login (wrong password first), character pagination, and guide creation with invalid-then-valid inputs — against the live API.

Data model

Three tables, one story.

Reference data seeded once, user content moderated, uploads linked per guide.

Characters Seeded
  • name from API
  • element, weapon reference
  • rarity, region reference
  • 92 rows read-only
BuildGuides User created
  • username, title validated
  • description 10–350 chars
  • character_id FK → Characters
  • status pending / approved
Uploads Optional
  • image file JPG / PNG
  • caption per image
  • guide_id FK → BuildGuides
  • many per guide 1‑to‑many
